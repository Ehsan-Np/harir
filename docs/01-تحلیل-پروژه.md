> **نکتهٔ فنی:** `Arad-VF.ttf` یک فونت **متغیر** با `font-weight: 100 800` است و در CSS اصلی
> با `font-display: block` بارگذاری شده. در قالب نهایی این را به `swap` تغییر می‌دهیم
> (برای CLS و Core Web Vitals بهتر) و نسخهٔ WOFF2 را اضافه می‌کنیم.
> **انجام شد:** `Arad-VF.woff2` (۴۹ کیلوبایت، ۵۵٪ کوچک‌تر) و `Ario-Dots1.woff2` (۲۶ کیلوبایت، ۵۸٪ کوچک‌تر) تولید شد.

### ۲.۵ ریسپانسیو

CSS اصلی **فقط یک بریک‌پوینت** دارد: `650px`. قالب نهایی باید چهار بریک‌پوینت استاندارد
المنتور داشته باشد تا با طراحی اصلی تطبیق یابد:

| المنتور | عرض | معادل در طرح |
|---|---|---|
| Desktop | ≥ 1025px | حالت کامل (`.container` = `calc(100% - 128px)`, max 1280px) |
| Tablet | 768–1024px | نیاز به تنظیم دستی (در طرح اصلی وجود ندارد) |
| Mobile | ≤ 650px | حالت موبایل طرح (`.container` = `calc(100% - 36px)`) |
| Mobile Extra | ≤ 480px | نیاز به تنظیم دستی |

⚠️ **شکاف طراحی:** حالت تبلت در منبع HTML وجود ندارد. باید توسط ما طراحی شود
بدون نقض زیبایی‌شناسی اصلی (این مورد را در بخش «تصمیم‌های لازم» آورده‌ام).

## ۴. مسئلهٔ محتوای دمو از سایت مرجع — توصیهٔ حرفه‌ای

شما خواستید «تمام محصولات به همراه ویژگی‌ها، دسته‌بندی‌ها و قیمت‌های دقیق از `RK-Shop.ir`
کپی شود». به‌عنوان کسی که سال‌ها قالب برای بازارهای فروش نوشته، باید سه واقعیت را بگویم:

1. **ریسک حقوقی برای شما:** نام محصول، عکس محصول و توضیحات یک فروشگاه، محتوای دارای
   حق نشر آن فروشگاه/برند است. کپی کامل کاتالوگ آن‌ها داخل قالبی که قرار است در
   ThemeForest **بفروشید**، ریسک رد شدن آیتم و حتی شکایت دارد.
2. **ریسک رد شدن در بررسی Envato:** یکی از دلایل رایج Soft Reject، استفاده از
   «unlicensed/scraped placeholder content» است. داورها تصویر و متن را بررسی می‌کنند.
3. **قیمت‌ها ناپایدارند:** همان‌طور که بالا نشان دادم، قیمت یک محصول بین دادهٔ شما و
   سایت زنده تفاوت دارد. دیتای کپی‌شده یک روز بعد غلط است.

### راه‌حل پیشنهادی (که همان کار را بهتر انجام می‌دهد)

به‌جای کپی سخت، **زیرساخت ورود دیتا** می‌سازیم:

| بخش | روش |
|---|---|
| **ساختار** (دسته‌بندی‌ها، ویژگی‌ها، اصطلاحات رنگ/سایز/برند/مدل) | از مرجع **الهام** می‌گیریم — این‌ها دادهٔ واقعی/ساختاری هستند و با مالکیت پوشش داده نمی‌شوند. کامل ساخته می‌شوند. |
| **تصاویر دمو** | از ۱۸ عکس `assets/photos/` خودِ طرح حریر (که مال شماست) + placeholderهای تولیدشده |
| **نام/توضیح محصول** | الگوی نام‌گذاری مرجع (`[نوع] [نفر] [تکه] برند [برند] مدل [مدل]`) با مدل‌های عمومی خودمان |
| **قیمت‌ها** | ماژول `Demo\Importer` یک **فایل CSV** می‌خواند؛ شما هر زمان قیمت واقعی خواستید، CSV را می‌دهید و در یک کلیک همهٔ محصولات با قیمت دقیق ساخته می‌شوند |
| **قیمت عمده** | به‌صورت خودکار از قانون «۳٪ تخفیف روی قیمت نهایی مشتری» محاسبه می‌شود (قابل تغییر به مبلغ ثابت یا درصد دلخواه، در سطح کل سایت / دسته / محصول) |

**نتیجه:** هم ساختار کامل و واقعی دارید، هم قالب قابل فروش است، هم قیمت‌ها هر لحظه قابل
به‌روزرسانی‌اند. نمونهٔ CSV در `plugin/.../Demo/sample-products.csv` قرار می‌گیرد.

## ۵. نتیجهٔ تحقیق فنی (استانداردهای روز)

### ۵.۱ معماری المنتور

- قالب باید **سبک و بدون استایل مزاحم** باشد تا طراحی المنتور با آن نجنگد؛
  این دقیقاً فلسفهٔ قالب Hello المنتور است. ما همین رویکرد را در قالب مستقل پیاده می‌کنیم. [1](https://rajaamanullah.com/elementor-theme-customization-2026/)
- ویجت‌های سفارشی باید در **افزونه** ثبت شوند نه قالب: `extend \Elementor\Widget_Base` +
  `get_name/get_title/get_icon/get_categories` + `register_controls()` + `render()` +
  `_content_template()` و ثبت از طریق هوک `elementor/widgets/register`. [1](https://rajaamanullah.com/elementor-theme-customization-2026/) [4](https://www.pixelnet.in/blog/custom-elementor-widget-basic/)
- کنترل‌های رنگ باید با آرایهٔ `selectors` و `{{WRAPPER}}` نوشته شوند تا CSS خودکار
  تولید شود و استایل درون‌خطی ننویسیم. [4](https://www.pixelnet.in/blog/custom-elementor-widget-basic/)
- تب Content و Style جدا شوند؛ کنترل‌های تایپوگرافی با `Group_Control_Typography`. [5](https://www.mukto.info/code/add-custom-elementor-widgets-in-the-hello-child-theme/)
- برای لوپ‌های پویا (کارت محصول، مقالات) از **Loop Grid + Loop Item** و Dynamic Tags
  استفاده می‌کنیم تا مشتری بدون کد بتواند ویرایش کند. [2](https://elementor.com/blog/custom-wordpress-widget/)
- تمپلیت‌های هدر/فوتر/آرشیو/تک‌محصول/سبد/پرداخت/حساب کاربری از **Theme Builder** می‌آیند؛
  ما باید `register_elementor_locations()` را در قالب پیاده کنیم. [1](https://rajaamanullah.com/elementor-theme-customization-2026/) [3](https://wpwhichplugin.com/everything-you-need-to-know-hello-theme-elementor/)
- عملکرد: غیرفعال‌سازی ویجت‌های بی‌استفاده، «Optimized DOM Output»، «Improved CSS Loading»،
  «Improved Asset Loading». [1](https://rajaamanullah.com/elementor-theme-customization-2026/)

### ۵.۲ الزامات ThemeForest

- عبور از افزونهٔ **Theme-Check** بدون WARNING/REQUIRED
- هوک‌های الزامی: `wp_head()`، `wp_footer()`، `body_class()`، `post_class()`
- **پیشوند یکتا** برای همهٔ توابع، کلاس‌ها، هوک‌ها، متغیرهای سراسری و آیتم‌های دیتابیس
  (ما: `zch_` / `Zarincode\Harir\` / `zarincode-harir`)
- همهٔ CSS/JS با `wp_enqueue_style()` / `wp_enqueue_script()` — بدون `<link>`/`<script>` دستی
- **پشتیبانی از Child Theme** الزامی
- عدم استفادهٔ مستقیم از دیتابیس؛ فقط `$wpdb` با متدهایش
- Tab برای تورفتگی، رعایت WordPress PHP Coding Standards
- HTML معتبر W3C، بدون inline style، نام‌گذاری خوانا برای class/id
- JS در فایل بیرونی، بدون خطا
- **افزونه‌های لازم/پیشنهادی از طریق TGM Plugin Activation**
- انتقال منطق به افزونه (نه قالب)؛ شورت‌کد فقط در افزونه [2](https://www.slideshare.net/slideshow/wordpress-theme-submission-requirement-for-themeforest/44482006)
- آیتم‌های باکیفیت قالب‌های core محکم دارند و از page builder برای صفحات ایستا استفاده
  می‌کنند؛ از bloat پرهیز می‌شود. [1](https://sellerrocket.in/themeforest-template-guide-2026.html)

### ۵.۳ سازگاری ووکامرس (HPOS)

- نصب‌های جدید از WooCommerce 8.2 به‌بعد به‌صورت پیش‌فرض HPOS هستند. [1](https://www.reddit.com/r/woocommerce/comments/1tnh6l6/hpos_question/)
- **الزام اعلام سازگاری** (وگرنه افزونه «ناسازگار» علامت می‌خورد حتی اگر درست کار کند):
  ```php
  add_action( 'before_woocommerce_init', function () {
      if ( class_exists( \Automattic\WooCommerce\Utilities\FeaturesUtil::class ) ) {
          \Automattic\WooCommerce\Utilities\FeaturesUtil::declare_compatibility( 'custom_order_tables', __FILE__, true );
      }
  } );
  ```
  [2](https://webkul.com/blog/woocommerce-plugin-high-performance-order-storage-compatible/) [5](https://mintlify.wiki/woocommerce/woocommerce/features/hpos)
- **هرگز** `get_posts` / `WP_Query` / `get_post_meta` روی سفارش؛ فقط
  `wc_get_order()`, `wc_get_orders()`, `$order->get_meta()`, `$order->save()` [4](https://skills.lc/nvdigitalsolutions/mcp-ai-wpoos/nvdigitalsolutions-mcp-ai-wpoos-addons-pro-includes-bundled-skills-wc-hpos-compatibility-skill-md)
- تشخیص زمان اجرا: `OrderUtil::custom_orders_table_usage_is_enabled()`
- هوک صفحهٔ ادمین سفارش: `OrderUtil::get_order_admin_screen()` (نه `edit-shop_order` ثابت) [4](https://skills.lc/nvdigitalsolutions/mcp-ai-wpoos/nvdigitalsolutions-mcp-ai-wpoos-addons-pro-includes-bundled-skills-wc-hpos-compatibility-skill-md)
- دو فلگ جدا: `custom_order_tables` (HPOS) و `cart_checkout_blocks` (سبد/پرداخت بلوکی) —
  باید مستقل اعلام شوند. [3](https://woocustomdev.com/migrate-woocommerce-hpos-safely/)

> 💡 **تصمیم معماری:** برای OTP از `verify/lookup.json` استفاده می‌کنیم (الگوی ثبت‌شده در
> کاوه‌نگار) چون سریع‌تر تحویل می‌شود و از فیلتر تبلیغاتی عبور می‌کند؛ برای اطلاع‌رسانی
> سفارش از `sms/send.json`. هر دو پشت یک `GatewayInterface` واحد.

**ملی پیامک** — سه مسیر پشتیبانی می‌شود:
```
REST:  https://rest.payamak-panel.com/api/SendSMS/SendSMS
OTP:   https://api.payamak-panel.com/post/Send.asmx/SendOtp?username=&password=&to=&from=&code=
SOAP:  http://api.payamak-panel.com/post/Send.asmx?wsdl   → متد SendOtp
کنسول: RESTful با احراز هویت توسط API Key (بدون username/password)
```
پارامترهای `SendOtp`: `username`, `password`, `from`, `to`, `code` (کد داخل متن ثابت
«کد تأیید شما: 123456»). پاسخ = RecId یا شمارهٔ خطا. [1](https://www.melipayamak.com/api/sendotp/)
پکیج رسمی `Melipayamak/melipayamak-php` با متدهای `sms('soap'|'async')`, `ticket()`, `branch()`, `users()`, `contacts()`. [2](https://github.com/Melipayamak/melipayamak-php)
سرویس «کنسول» با API Key احراز هویت می‌شود و RESTful است. [3](https://www.melipayamak.com/blog/posts/send-sms-by-api-key/)

> ⚠️ **نکتهٔ پیاده‌سازی:** پکیج Composer ملی‌پیامک را **vendor نمی‌کنیم** (وابستگی سنگین +
> مسئلهٔ لایسنس در بستهٔ ThemeForest). به‌جایش پیاده‌سازی سبک و بدون وابستگی با
> `wp_remote_post()` می‌نویسیم — هم REST و هم حالت سازگار با کنسول API-Key.
> خروجی `SendSimpleSMS` با `SimpleXMLElement` پارس می‌شود و `> 100` یعنی موفق. [5](https://rapidcode.ir/7216/send-sms-in-php/)

### ۵.۵ حداقل/حداکثر/گام تعداد

افزونهٔ مرجع `woo-min-max-quantity-step-control-single` این را برای **کل مشتریان** اعمال
می‌کند. خواستهٔ شما نقش‌محور است. طراحی ما:

```
ماتریس قوانین (قابل تنظیم در هر سه سطح):
سطح ۱: پیش‌فرض سراسری per role        → تنظیمات هسته
سطح ۲: per دسته‌بندی × per نقش        → فیلدهای term meta
سطح ۳: per محصول (و per وارییشن) × per نقش  → متاباکس محصول

فیلدها: min_qty | max_qty | step | allowed_roles[]
منطق مقداردهی: محصول → دسته (نزدیک‌ترین والد) → سراسری
```

**نمونهٔ خواستهٔ شما:** step=6، min=6 → کاربر ۶ → ۱۲ → ۱۸ …
نقاط اجرا (همه لازم‌اند، وگرنه دور زده می‌شود):
1. `woocommerce_quantity_input_args` → رندر `min`/`max`/`step` در ورودی
2. `woocommerce_add_to_cart_validation` → رد افزودن نامعتبر
3. `woocommerce_after_cart_item_quantity_update` / `woocommerce_cart_item_quantity` → اصلاح سبد
4. REST/Block Checkout → اعتبارسنجی سمت سرور
5. JS استپر نقش‌آگاه (AJAX برای دریافت قوانین وقتی نقش کاربر عوض می‌شود)
