### ۲.۱ سلسله‌مراتب تمپلیت و المنتور

قالب برای **هر** Location هم مسیر المنتور را ثبت می‌کند و هم تمپلیت PHP بومی دارد:

```php
// inc/elementor/locations.php
add_action( 'elementor/theme/register_locations', function ( $manager ) {
    foreach ( [ 'header','footer','single','archive','single-product',
                'product-archive','search','404','page' ] as $loc ) {
        $manager->register_location( $loc );
    }
    // هوک‌های اختصاصی ووکامرس
    foreach ( [ 'cart','checkout','my-account','order-received' ] as $loc ) {
        $manager->register_location( $loc );
    }
} );
```

سپس در هر تمپلیت:

```php
if ( ! zch_elementor_location_exists( 'header' ) ) {
    get_template_part( 'template-parts/header/masthead' );
}
```

→ با Elementor Pro کاربر همه‌چیز را در Theme Builder می‌سازد؛
بدون Pro هم قالب کاملاً کار می‌کند. **هیچ‌وقت صفحهٔ خالی نمی‌شود.**

## ۴. طراحی ماژول‌های بحرانی

### ۴.۱ موتور قیمت عمده (`Wholesale\PriceEngine`) ⭐

**مدل داده (product meta):**

| Meta key | نوع | توضیح |
|---|---|---|
| `_zch_wholesale_enabled` | bool | فعال بودن قیمت عمده برای این محصول |
| `_zch_wholesale_mode` | enum | `percent` \| `fixed` \| `price` (مبلغ مطلق) |
| `_zch_wholesale_base` | enum | `regular` (بدون تخفیف) \| `sale` (با تخفیف) \| `customer_final` (قیمت نهایی مشتری) |
| `_zch_wholesale_value` | float | مقدار درصد یا مبلغ |
| `_zch_wholesale_price` | float | خروجی محاسبه (کش‌شده برای سرعت فهرست‌ها) |
| `_zch_wholesale_note` | string | متن دلخواه کنار قیمت (اختیاری) |

**زنجیرهٔ تصمیم (Resolution chain):**

```
۱. وارییشن محصول (اگر variable باشد) → meta وارییشن
۲. خود محصول                          → meta محصول
۳. دسته‌بندی محصول (نزدیک‌ترین والد)   → term meta
۴. پیش‌فرض سراسری                      → option zch_wholesale_defaults
   → پیش‌فرض کارخانه: base=customer_final, mode=percent, value=3
```

**الگوریتم:**

```php
public function resolve( int $product_id, ?int $variation_id = null ): PriceResult {
    $product   = wc_get_product( $variation_id ?: $product_id );
    $regular   = (float) $product->get_regular_price();
    $sale      = (float) $product->get_sale_price();
    $customer  = $sale > 0 ? $sale : $regular;          // قیمت نهایی مشتری

    $rule = $this->find_rule( $product_id, $variation_id );   // زنجیرهٔ ۴ سطحی
    if ( ! $rule['enabled'] ) return PriceResult::not_available();

    $base = match ( $rule['base'] ) {
        'regular'        => $regular,
        'sale'           => $sale > 0 ? $sale : $regular,
        'customer_final' => $customer,
    };

    $wholesale = match ( $rule['mode'] ) {
        'percent' => $base - ( $base * $rule['value'] / 100 ),
        'fixed'   => $base - $rule['value'],
        'price'   => $rule['value'],          // مبلغ مطلق، مستقل از پایه
    };

    $wholesale = max( 0, round( $wholesale, wc_get_price_decimals() ) );

    return new PriceResult(
        regular:   $regular,
        customer:  $customer,
        wholesale: $wholesale,
        saved:     $customer - $wholesale,
        percent:   $customer > 0 ? round( ( $customer - $wholesale ) / $customer * 100 ) : 0,
        rule:      $rule,
    );
}
```

**مثال واقعی شما:**

| ورودی | مقدار |
|---|---|
| قیمت بدون تخفیف (`regular`) | ۸٬۳۵۵٬۰۰۰ |
| قیمت مشتری (`customer_final`) | ۷٬۶۸۷٬۰۰۰ (۸٪ تخفیف عمومی) |
| قانون عمده | `base=customer_final`, `mode=percent`, `value=3` |
| محاسبه | ۷٬۶۸۷٬۰۰۰ × ۰٫۹۷ = **۷٬۴۵۶٬۳۹۰** |
| صرفه‌جویی همکار | ۲۳۰٬۶۱۰ تومان |
| درصد نسبت به قیمت بدون تخفیف | ۱۰٫۸٪ → همین عدد در متن توضیحی نمایش داده می‌شود |

**خروجی بصری (مطابق خواستهٔ شما):**
```
۸٬۳۵۵٬۰۰۰  ← خط‌خورده
۷٬۴۵۶٬۳۹۰ تومان  ← قیمت نهایی همکار
برچسب: «قیمت همکاری»
متن: «قیمت این محصول ۸٬۳۵۵٬۰۰۰ تومان بوده که برای مشتریان با تخفیف
       ۷٬۶۸۷٬۰۰۰ تومان محاسبه می‌شود و برای شما به‌عنوان همکار،
       با ۳٪ تخفیف اضافی، ۷٬۴۵۶٬۳۹۰ تومان ارائه می‌گردد.»
```
این متن از یک **الگوی قابل ویرایش** در تنظیمات تولید می‌شود (با متغیرهای
`{regular}`, `{customer}`, `{wholesale}`, `{percent}`, `{saved}`) تا شما بتوانید
لحن آن را بدون کد عوض کنید.

**نقاط اتصال به ووکامرس:**

| هوک | کاربرد |
|---|---|
| `woocommerce_product_get_price` / `get_sale_price` | جایگزینی قیمت برای نقش عمده |
| `woocommerce_get_price_html` | رندر markup دو/سه‌قیمتی |
| `woocommerce_product_variation_get_price` | پشتیبانی وارییشن |
| `woocommerce_before_calculate_totals` | اصلاح قیمت آیتم سبد (سرچشمهٔ حقیقت) |
| `woocommerce_variation_prices` | محدودهٔ قیمت در variable products |
| `woocommerce_structured_data_product` | **خنثی‌سازی** — اسکیما همیشه قیمت عمومی |

> 🔒 **اصل امنیتی:** `PriceEngine::get_price_for_user()` ابتدا
> `zch_user_can_view_wholesale( $user )` را بررسی می‌کند. اگر false باشد،
> همیشه قیمت عمومی برگردانده می‌شود — حتی اگر کسی پارامتر را دستکاری کند.
> خزنده‌ها، کاربران مهمان، RSS، REST API عمومی و اسکیما **همیشه** قیمت عمومی می‌گیرند.

### ۴.۲ قوانین تعداد (`Wholesale\QuantityRules`) ⭐

**مدل داده — یک ردیف به ازای هر نقش:**

| Meta key | مثال برای `zch_wholesale` | مثال برای `customer` |
|---|---|---|
| `_zch_qty_min` | 6 | 1 |
| `_zch_qty_max` | 600 | 5 |
| `_zch_qty_step` | 6 | 1 |
| `_zch_qty_rules` (آرایه) | `['customer'=>[...], 'zch_wholesale'=>[...], 'guest'=>[...]]` | |

**API:**
```php
QuantityRules::for_product( $product_id, $role = null ): array
// → [ 'min' => int, 'max' => int, 'step' => int, 'source' => 'product|category|global' ]

QuantityRules::normalize( $product_id, $qty ): int
// گرد کردن به نزدیک‌ترین مضرب step در بازهٔ [min, max]
```

**رفتار خواستهٔ شما:** `min=6, step=6` → کلیک روی «+»: ۶ → ۱۲ → ۱۸
`normalize(7) = 6` (گرد به پایین) یا `12` (گرد به بالا) — **قابل تنظیم** در تنظیمات
(`rounding = down|up|nearest`)، پیش‌فرض `down` تا مشتری غافلگیر نشود.

**اعتبارسنجی سمت سرور (اجباری در هر ۴ نقطه):**

### ۴.۳ احراز هویت نقش‌آگاه (`Auth`)

**حالت‌های قابل تنظیم توسط مدیر (هرکدام مستقل):**

| تنظیم | گزینه‌ها |
|---|---|
| `zch_register_with` | `mobile` · `email` · `mobile_or_email` |
| `zch_login_with` | `mobile_otp` · `mobile_password` · `email_password` · `username_password` · `mobile_otp_or_password` · `any` |
| `zch_otp_required_for` | `register` · `login` · `password_reset` · `phone_change` · `wholesale_application` |
| `zch_role_selection` | `on_register` (کاربر نقش را انتخاب کند) · `after_approval` |

**اصل «بدون خلل» (خواستهٔ صریح شما):**
```php
add_filter( 'authenticate', [ $this, 'authenticate' ], 20, 3 );

public function authenticate( $user, $username, $password ) {
    // ۱) اگر ورودی ما نیست (مثلاً username خالی) → دست نمی‌زنیم
    if ( ! $this->is_ours( $username, $password ) ) return $user;

    // ۲) اگر وردپرس خودش موفق شده → نتیجهٔ او را حفظ می‌کنیم
    if ( $user instanceof \WP_User ) return $user;

    // ۳) فقط در این حالت مسیر اختصاصی ما اجرا می‌شود
    return $this->try_otp_or_phone_login( $username, $password );
}
```
→ هرگز `wp_authenticate` جایگزین نمی‌شود؛ کاربران قبلی با همان username/password
وارد می‌شوند؛ اگر افزونه غیرفعال شود هیچ‌چیز نمی‌شکند.

**امنیت OTP (`Auth\Otp`):**

| کنترل | مقدار |
|---|---|
| طول کد | ۵ رقم (قابل تنظیم ۴–۸) |
| ذخیره‌سازی | `hash('sha256', $code . $salt)` — کد خام هرگز ذخیره نمی‌شود |
| TTL | ۱۲۰ ثانیه |
| حداکثر تلاش | ۵ بار → سپس باطل‌سازی و درخواست کد جدید |
| Rate limit ارسال | ۱ پیامک در ۱۲۰ ثانیه برای هر شماره · ۵ در ساعت برای هر شماره · ۱۰ در روز برای هر IP |
| Nonce | یک‌بارمصرف، متصل به session |
| قفل حساب | ۱۵ دقیقه پس از ۱۰ تلاش ناموفق |
| لاگ | جدول `zch_otp` با `ip`, `ua_hash`, `attempts`, `consumed_at` |
| نشت | پاسخ API یکسان برای «شماره وجود ندارد» و «کد غلط است» (جلوگیری از user enumeration) |

**گردش ثبت‌نام (مطابق خواستهٔ شما):**
```
کاربر نقش را انتخاب می‌کند
 ├─ «حساب مشتری»     → OTP → ساخت کاربر با نقش customer → فعال فوری ✅
 └─ «حساب همکار عمده» → OTP → فرم کسب‌وکار (نام کسب‌وکار, مسئول پیگیری,
                              موبایل, شهر, نوع همکاری, مدارک)
                          → ساخت کاربر با نقش zch_wholesale_pending ⏳
                          → اعلان به مدیر + تیکت
                          → تأیید مدیر → نقش zch_wholesale + ایمیل/پیامک خوش‌آمد
                          → رد → بازگشت به customer + اطلاع‌رسانی با دلیل
```
نقش میانی `zch_wholesale_pending` **اجازهٔ دیدن قیمت عمده را ندارد** —
`RoleGuard` فقط `zch_wholesale` تأییدشده را می‌پذیرد.

**ارتقاء/تنزیل (`Roles\RoleSwitch`):**
- درخواست از پنل مشتری → فرم + دلیل + مدارک → وضعیت `pending`
- مدیر: تأیید / رد / درخواست تکمیل
- **حفظ کامل داده:** هیچ متا، سفارش، علاقه‌مندی یا کش‌بکی پاک نمی‌شود؛ فقط `wp_user_role` عوض می‌شود
- لاگ تغییر نقش در جدول `zch_role_requests` با `from_role`, `to_role`, `admin_id`, `note`

## ۷. استاندارد کیفیت (تعریف «تمام» برای هر ماژول)

هر ماژول فقط وقتی کامل است که همهٔ این‌ها را داشته باشد:

- [ ] پیشوند یکتا در همه‌چیز (تابع، کلاس، هوک، meta، option، جدول)
- [ ] `defined( 'ABSPATH' ) || exit;` در بالای هر فایل
- [ ] همهٔ خروجی‌ها escape شده (`esc_html`, `esc_attr`, `esc_url`, `wp_kses_post`)
- [ ] همهٔ ورودی‌ها sanitize شده + nonce برای هر فرم/AJAX
- [ ] `current_user_can()` قبل از هر عملیات حساس
- [ ] `$wpdb->prepare()` برای همهٔ کوئری‌ها
- [ ] متن‌ها با `__()` / `esc_html__()` و Text Domain درست
- [ ] بدون تماس مستقیم با `wp_posts`/`wp_postmeta` برای سفارش‌ها
- [ ] Assetها فقط با `wp_enqueue_*` و فقط در صفحهٔ لازم
- [ ] هوک‌های سفارشی مستند شده (`/** Fires when… */`)
- [ ] قابل غیرفعال‌سازی با فیلتر (`zch/module/enabled`)
- [ ] بدون خطا با `WP_DEBUG = true` و `WP_DEBUG_LOG`
- [ ] سازگار با PHP 7.4 تا 8.4 (بدون deprecated)

## ۸. عملکرد و SEO

### ۸.۱ بودجهٔ عملکرد
| معیار | هدف |
|---|---|
| CSS قالب (بدون المنتور) | < ۴۰ KB gzip |
| JS قالب | < ۲۵ KB gzip، بدون jQuery |
| فونت‌ها | ۲ فایل WOFF2 = ۷۵ KB، `preload` + `swap` |
| LCP | < ۲٫۵s |
| CLS | < ۰٫۱ (ابعاد صریح روی همهٔ تصویر و فونت) |
| INP | < ۲۰۰ms |
| Query در صفحهٔ محصول | < ۲۵ |

### ۸.۲ اقدام‌ها
- WOFF2 + `font-display: swap` + `<link rel="preload">` برای فونت بالای صفحه ✅ (فونت‌ها تبدیل شدند)
- ثبت سایزهای تصویر سفارشی و استفاده از `wp_get_attachment_image` (srcset + sizes + width/height)
- Sprite برای SVGها به‌جای ۲۰۰ بار تکرار درون‌خطی
- `defer` برای JS غیربحرانی، `dns-prefetch`/`preconnect` برای منابع خارجی
- Asset per-widget در المنتور (فایل ویجت فقط وقتی رندر شود)
- کش قیمت عمده در `_zch_wholesale_price` تا فهرست‌ها N+1 query نزنند
- `DONOTCACHEPAGE` برای کاربران لاگین‌کرده و صفحات دارای قیمت نقش‌آگاه
- حذف emoji، embed، و `wp-json` غیرضروری
- Load More به‌جای صفحه‌بندی سنگین (مطابق طرح «نمایش محصولات بیشتر»)

### ۸.۳ اسکیما (JSON-LD)
| نوع | کجا |
|---|---|
| `Organization` + `WebSite` + `SearchAction` | سایت‌واید |
| `Product` + `Offer` + `AggregateRating` | صفحهٔ محصول — **همیشه با قیمت عمومی** |
| `BreadcrumbList` | همهٔ صفحات دارای `.page-crumb` |
| `ItemList` | آرشیو و کاتالوگ |
| `Article` + `Person` | نوشته وبلاگ |
| `FAQPage` | صفحهٔ پرسش‌های متداول |
| `LocalBusiness` | تماس با ما |
| `ReturnPolicy` + `ShippingDetails` | گارانتی و بازگشت / حمل |

> 🔒 قیمت عمده **هرگز** در اسکیما، RSS، REST عمومی یا `<meta>` ظاهر نمی‌شود.

### ۸.۴ دسترس‌پذیری
- Skip link · focus visible · focus trap در منوی موبایل و مودال‌ها
- `aria-expanded`/`aria-controls` روی دراپ‌داون‌ها
- `role="status"` برای پیام‌های AJAX و تایمر OTP
- برچسب قابل‌دسترس روی همهٔ ورودی‌ها (کلاس `.field` طرح حفظ شود ولی `<label for>` واقعی)
- کنتراست رنگ: `--muted (#6b5963)` روی `--bg (#fbf9f7)` = ۶٫۱:۱ ✅ (AA)
- `prefers-reduced-motion` برای گردونه و انیمیشن‌ها
- کیبورد کامل برای گالری محصول و استپر تعداد
